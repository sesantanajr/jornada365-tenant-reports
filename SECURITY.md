# Security

Use **Security → Report a vulnerability** on GitHub if the option is available. If you need a different channel, open an issue requesting a private contact and share the technical details in private. Include the affected versions, the observed impact and a minimal example with fictional data. Remove access tokens, cookies, authorization headers and personal identifiers.

In version 2.0, the public portal link preview uses the WordPress page’s featured image or the bundled artwork. Choose an image suitable for public sharing. If a preview exposes tenant information unexpectedly, include the affected page and whether a featured image was configured in your private report.

## Segurança

Para relatar uma vulnerabilidade, abra a guia **Security** do repositório e use **Report a vulnerability**, se a opção estiver disponível. Caso precise de outro canal, abra uma issue pedindo um meio de contato privado e reserve os detalhes técnicos para esse canal.

No relato privado, informe a versão do plugin, do WordPress e do PHP, o recurso afetado, o impacto observado e um exemplo com dados fictícios. Remova tokens, cookies, cabeçalhos de autorização e identificadores pessoais das evidências.

Na versão 2.0, a prévia do link público usa a imagem destacada da página do WordPress ou a arte incluída no plugin. Escolha uma imagem adequada à divulgação pública. Se a prévia exibir dados do tenant de forma inesperada, informe no relato privado qual página foi afetada e se havia uma imagem destacada configurada.

Para validar uma correção de permissões ou de ações do Intune e do Exchange, use uma instalação WordPress em HTTPS e recursos de um tenant de homologação.
