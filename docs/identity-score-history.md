# Identity Score history

## English

**Security → Identity Score → Portal history** starts off for each tenant. A Microsoft Entra Global Administrator or Privileged Role Administrator can enable it. The portal verifies that role with the tenant when the setting changes. The report still requires its existing Graph read permission and tenant access. To erase the history, choose **Turn off and erase history** and confirm. The same control is available under **Settings → Privacy and data**, including when the report module is off.

When an authorized user generates the report, WordPress reads the available Graph pages and keeps the latest valid observation in each of the current and preceding 23 UTC calendar months. The first collection can backfill the dates Graph still supplies. The database contains the tenant ID, measurement timestamps and earned/available points, plus technical revision and last-check metadata. User details, recommendation text, imported files and delegated tokens are outside this archive. Closing the tab ends its work. On shared hosting the existing hourly WP-Cron job removes expired months as the site receives traffic. Reads also exclude expired months. Disabling tracking, suspending or deleting the tenant, or uninstalling the plugin erases its archive in the live WordPress database. The hosting provider controls separate backup retention.

The monthly table and Excel identify the source of each closing. **Microsoft Graph** denotes the current response, **Portal history** an earlier official measurement kept in WordPress, and **Local file** a file the user imported in this tab. An archived closing contributes one known measurement day. Missing months remain blank. Generate the report regularly to grow coverage. Reopening a report cached in the same tab displays its last result. **Generate again** makes a fresh request.

Microsoft describes an evaluation every 24 hours and a beta API for reading historical identity scores. Its documentation gives no guaranteed historical window or two-year backfill. The separate Microsoft Defender Secure Score resource documents its own 90-day default. [Entra scoring](https://learn.microsoft.com/en-us/entra/identity/monitoring-health/concept-identity-secure-score) · [Entra Graph API and permissions](https://learn.microsoft.com/en-us/graph/api/recommendation-tenantsecurescores?view=graph-rest-beta) · [Defender Secure Score](https://learn.microsoft.com/en-us/graph/api/resources/securescore?view=graph-rest-1.0)

For unattended collection, a tenant can operate its own scheduled collector outside WordPress. An Azure Automation managed identity can receive the **application** permission `DirectoryRecommendations.Read.All` in that tenant. A separate process can retain its observations in tenant-controlled storage and produce a JSON file for local import. This is a separate administrative grant and the Graph endpoint is beta. The default per-tenant portal uses the signed-in user's delegated access and requires no Azure scheduler. [Schedule the collector](score-collector.md#english) · [Azure Automation managed identity](https://learn.microsoft.com/en-us/azure/automation/enable-managed-identity-for-automation) · [Grant Graph permissions to a managed identity](https://learn.microsoft.com/en-us/powershell/entra-powershell/grant-api-permissions-managed-identity)

## Português

**Segurança → Identity Score → Histórico do portal** começa desativado em cada tenant. Um Administrador Global ou Administrador de Funções Privilegiadas do Microsoft Entra pode ativá-lo. O portal verifica essa função junto ao tenant ao alterar a opção. O relatório continua exigindo a permissão de leitura do Graph e acesso ao tenant. Para apagar o histórico, selecione **Desativar e apagar histórico** e confirme. O controle também está em **Configurações → Privacidade e dados**, inclusive com o módulo de relatório desabilitado.

Quando alguém autorizado gera o relatório, o WordPress consulta as páginas disponíveis no Graph e mantém a última medição válida do mês UTC atual e dos 23 anteriores. A primeira consulta pode recuperar datas anteriores que o Graph ainda disponibiliza. O banco guarda o ID do tenant, a data de cada medição e os pontos obtidos e possíveis, além da revisão técnica e da data da última consulta. O arquivo de histórico não inclui usuários, textos de recomendações, arquivos importados ou tokens delegados. A coleta depende de uma sessão ativa. Na hospedagem compartilhada, o WP-Cron já instalado remove os meses vencidos na manutenção horária, conforme o site recebe visitas. A consulta também exclui os meses vencidos. Desativar o histórico, suspender ou excluir o tenant ou desinstalar o plugin apaga o arquivo no banco ativo do WordPress. A retenção de backups segue as regras da hospedagem.

A tabela mensal e o Excel identificam a origem de cada fechamento. **Microsoft Graph** identifica a resposta atual, **Histórico do portal** indica uma medição oficial de consulta anterior conservada no WordPress e **Arquivo local** indica um arquivo importado nesta aba. Um fechamento arquivado representa um único dia conhecido. Meses sem medição ficam em branco. Gere o relatório periodicamente para ampliar a cobertura. Reabrir um relatório já consultado na mesma aba exibe seu último resultado. **Gerar novamente** faz outra consulta.

A Microsoft descreve uma avaliação a cada 24 horas e uma API beta com pontuações históricas de identidade. A documentação não especifica uma janela garantida de retenção nem acesso retroativo a dois anos. O recurso de pontuação do Microsoft Defender apresenta retenção padrão própria de 90 dias. [Pontuação do Entra](https://learn.microsoft.com/pt-br/entra/identity/monitoring-health/concept-identity-secure-score) · [API e permissões do Entra](https://learn.microsoft.com/pt-br/graph/api/recommendation-tenantsecurescores?view=graph-rest-beta) · [Pontuação do Defender](https://learn.microsoft.com/pt-br/graph/api/resources/securescore?view=graph-rest-1.0)

Para coleta sem usuário conectado, a empresa pode agendar um coletor fora do WordPress. Uma identidade gerenciada do Azure Automation pode receber a permissão **de aplicativo** `DirectoryRecommendations.Read.All` no próprio tenant. O processo retém as observações em armazenamento controlado pela empresa e pode produzir um JSON para importação local. Esse modo exige uma concessão administrativa separada e usa a API beta. O portal padrão por tenant consulta com a identidade delegada de quem está conectado e dispensa agendamento no Azure.
