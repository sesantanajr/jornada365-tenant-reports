# Identity Score history

## English

The report and its Excel workbook open on 24 consecutive UTC calendar months. The chart groups consecutive months without an observation and displays each measured month. The monthly table, Excel chart and worksheet retain every month. **Coverage by source** lists the valid date range, distinct measured days and months, and number of closings supplied by each source in the selected period. A zero-point score is a measurement.

To recover earlier observations, open **Add earlier history files**, select one or more JSON archives for the same tenant, and optionally save the merged file. Files are checked together and merged by UTC day in this tab. Imported observations keep the **Local file** label in the display and export and are never written into the portal's official archive. The Graph operation documents no date-range parameters or 24-month retention. The portal follows each server-provided continuation link. A complete response can still contain only recent dates. Older missing months require an existing archive. [Graph history operation](https://learn.microsoft.com/en-us/graph/api/recommendation-tenantsecurescores?view=graph-rest-beta) · [Graph paging](https://learn.microsoft.com/en-us/graph/paging)

On an installation using the operator's multi-tenant application, **Portal history → Authorize daily collection** is a separate tenant opt-in. The application must already hold `DirectoryRecommendations.Read.All` or its read/write equivalent in that tenant. The portal requests no additional permission. WP-Cron reads one score page per work item and resumes the supplied paging cursor. The next cycle becomes due 24 hours after the last page. The host must execute WP-Cron for scheduled runs. **Pause daily collection** keeps earlier closings. Turning off portal history erases both the archive and schedule. The default per-tenant sign-in model uses the external collector below for unattended collection.

**Security → Identity Score → Portal history** starts off for each tenant. A Microsoft Entra Global Administrator or Privileged Role Administrator can enable it. The portal verifies that role with the tenant when the setting changes. The report still requires its existing Graph read permission and tenant access. To erase the history, choose **Turn off and erase history** and confirm. The same control is available under **Settings → Privacy and data**, including when the report module is off.

When an authorized user generates the report, WordPress reads the available Graph pages and keeps the latest valid observation in each of the current and preceding 23 UTC calendar months. The first collection can backfill the dates Graph still supplies. The database contains the tenant ID, measurement timestamps and earned/available points, plus technical revision and last-check metadata. User details, recommendation text, imported files and delegated tokens are outside this archive. In the delegated model an interactive collection ends when the tab closes. On shared hosting the existing hourly WP-Cron job removes expired months as the site receives traffic. Reads also exclude expired months. Disabling tracking, suspending or deleting the tenant, or uninstalling the plugin erases its archive in the live WordPress database. The hosting provider controls separate backup retention.

The monthly table and Excel identify the source of each closing. **Microsoft Graph** denotes the current response, **Portal history** an earlier official measurement kept in WordPress, and **Local file** a file the user imported in this tab. An archived closing contributes one known measurement day. Missing months remain blank. Generate the report regularly to grow coverage. Reopening a report cached in the same tab displays its last result. **Generate again** makes a fresh request.

Microsoft describes an evaluation every 24 hours and a beta API for reading historical identity scores. Its documentation gives no guaranteed historical window or two-year backfill. The separate Microsoft Defender Secure Score resource documents its own 90-day default. [Entra scoring](https://learn.microsoft.com/en-us/entra/identity/monitoring-health/concept-identity-secure-score) · [Entra Graph API and permissions](https://learn.microsoft.com/en-us/graph/api/recommendation-tenantsecurescores?view=graph-rest-beta) · [Defender Secure Score](https://learn.microsoft.com/en-us/graph/api/resources/securescore?view=graph-rest-1.0)

For unattended collection, a tenant can operate its own scheduled collector outside WordPress. An Azure Automation managed identity can receive the **application** permission `DirectoryRecommendations.Read.All` in that tenant. A separate process can retain its observations in tenant-controlled storage and produce a JSON file for local import. This is a separate administrative grant and the Graph endpoint is beta. The default per-tenant portal uses the signed-in user's delegated access and requires no Azure scheduler. [Schedule the collector](score-collector.md#english) · [Azure Automation managed identity](https://learn.microsoft.com/en-us/azure/automation/enable-managed-identity-for-automation) · [Grant Graph permissions to a managed identity](https://learn.microsoft.com/en-us/powershell/entra-powershell/grant-api-permissions-managed-identity)

## Português

O relatório e o Excel começam com 24 meses consecutivos do calendário UTC. O gráfico agrupa os meses consecutivos sem medição e exibe cada mês medido. A tabela mensal, o gráfico do Excel e a planilha mantêm todos os meses. **Cobertura por origem** apresenta as datas extremas válidas, a quantidade de dias e meses medidos e o número de fechamentos de cada origem no período escolhido. Zero ponto é uma medição válida.

Para recuperar medições anteriores, abra **Complementar com arquivos anteriores**, selecione um ou mais arquivos JSON do mesmo tenant e, se desejar, salve o arquivo consolidado. Os arquivos são verificados em conjunto e reunidos por dia UTC nesta aba. As observações importadas mantêm a identificação **Arquivo local** na tela e na exportação. O arquivo oficial do WordPress recebe apenas observações consultadas no Graph. A documentação da operação não especifica parâmetros de intervalo de datas nem retenção de 24 meses. O portal percorre os links de paginação fornecidos pelo serviço. Uma resposta completa pode conter apenas datas recentes. Para recuperar meses anteriores ausentes, é preciso um arquivo já existente. [Histórico no Graph](https://learn.microsoft.com/pt-br/graph/api/recommendation-tenantsecurescores?view=graph-rest-beta) · [Paginação no Graph](https://learn.microsoft.com/pt-br/graph/paging)

Nas instalações que usam o aplicativo multitenant do operador, **Histórico do portal → Autorizar coleta diária** é uma autorização adicional por tenant. O aplicativo precisa já ter `DirectoryRecommendations.Read.All` ou a equivalente de leitura e gravação nesse tenant. O portal não solicita outra permissão. O WP-Cron consulta uma página por execução e retoma a paginação a partir do cursor do Graph. O ciclo seguinte vence 24 horas após a última página. O agendamento depende da execução do WP-Cron na hospedagem. **Pausar coleta diária** preserva os fechamentos anteriores. Desativar o histórico do portal apaga o arquivo e o agendamento. No modelo padrão com aplicativo por tenant, o coletor externo abaixo permite a coleta sem usuário conectado.

**Segurança → Identity Score → Histórico do portal** começa desativado em cada tenant. Um Administrador Global ou Administrador de Funções Privilegiadas do Microsoft Entra pode ativá-lo. O portal verifica essa função junto ao tenant ao alterar a opção. O relatório continua exigindo a permissão de leitura do Graph e acesso ao tenant. Para apagar o histórico, selecione **Desativar e apagar histórico** e confirme. O controle também está em **Configurações → Privacidade e dados**, inclusive com o módulo de relatório desabilitado.

Quando alguém autorizado gera o relatório, o WordPress consulta as páginas disponíveis no Graph e mantém a última medição válida do mês UTC atual e dos 23 anteriores. A primeira consulta pode recuperar datas anteriores que o Graph ainda disponibiliza. O banco guarda o ID do tenant, a data de cada medição e os pontos obtidos e possíveis, além da revisão técnica e da data da última consulta. O arquivo de histórico não inclui usuários, textos de recomendações, arquivos importados ou tokens delegados. No modelo delegado, a coleta interativa depende de uma sessão ativa. Na hospedagem compartilhada, o WP-Cron já instalado remove os meses vencidos na manutenção horária, conforme o site recebe visitas. A consulta também exclui os meses vencidos. Desativar o histórico, suspender ou excluir o tenant ou desinstalar o plugin apaga o arquivo no banco ativo do WordPress. A retenção de backups segue as regras da hospedagem.

A tabela mensal e o Excel identificam a origem de cada fechamento. **Microsoft Graph** identifica a resposta atual, **Histórico do portal** indica uma medição oficial de consulta anterior conservada no WordPress e **Arquivo local** indica um arquivo importado nesta aba. Um fechamento arquivado representa um único dia conhecido. Meses sem medição ficam em branco. Gere o relatório periodicamente para ampliar a cobertura. Reabrir um relatório já consultado na mesma aba exibe seu último resultado. **Gerar novamente** faz outra consulta.

A Microsoft descreve uma avaliação a cada 24 horas e uma API beta com pontuações históricas de identidade. A documentação não especifica uma janela garantida de retenção nem acesso retroativo a dois anos. O recurso de pontuação do Microsoft Defender apresenta retenção padrão própria de 90 dias. [Pontuação do Entra](https://learn.microsoft.com/pt-br/entra/identity/monitoring-health/concept-identity-secure-score) · [API e permissões do Entra](https://learn.microsoft.com/pt-br/graph/api/recommendation-tenantsecurescores?view=graph-rest-beta) · [Pontuação do Defender](https://learn.microsoft.com/pt-br/graph/api/resources/securescore?view=graph-rest-1.0)

Para coleta sem usuário conectado, a empresa pode agendar um coletor fora do WordPress. Uma identidade gerenciada do Azure Automation pode receber a permissão **de aplicativo** `DirectoryRecommendations.Read.All` no próprio tenant. O processo retém as observações em armazenamento controlado pela empresa e pode produzir um JSON para importação local. Esse modo exige uma concessão administrativa separada e usa a API beta. O portal padrão por tenant consulta com a identidade delegada de quem está conectado e dispensa agendamento no Azure.
